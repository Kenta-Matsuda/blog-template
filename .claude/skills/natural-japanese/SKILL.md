# 自然な日本語で書く

このスキルの例は、実際の記事「[AWS試験を初めて英語で受けて分かったこと](https://qiita.com/kenken38/items/bd9ac1951e42b4fb8aa7)」の下書きと公開版の差分から取っている。「AI の下書き」はエージェントが書いた文で、「著者の公開版」は著者が手で直した文である。末尾の括弧は `LESSONS.md` の ID を示す。

## 0. AI 臭さには 2 種類ある

実際の記事では、2 種類の AI 臭さが順番に出た。

| 種類 | 症状 | 実際の例 |
|---|---|---|
| 飾りすぎ | 比喩、決め台詞、絵文字、枠、太字が多い | 「AIに地図を描いてもらってから自分で歩く」「ラスボスは試験じゃなく英語だった」 |
| 硬すぎ | 飾りは無いが、説明書のような文が同じ調子で続く。著者の感情と文のつながりが無い | 「私はこの読み方を英語の受験で身につけました。日本語の試験でも使える読み方だと思います。」 |

飾りを消すだけでは、自然な文にならない。エージェントが飾りを消して主語を補った版を、著者はさらに手で直した。著者が直したのは、文のつながり、語尾、具体的な事実、著者の感情である。そのため、次の章では両方の直し方を順に示す。（L003, L023）

## 1. 直す順序

次の順序で直す。前の段階の直しで文が変わるため、順序を入れ替えない。

### 1-1. 文の骨格をそろえる

主語、述語、目的語を、明らかなとき以外は省かない。名詞を並べただけの言い方と、体言止めの連続をやめる。（L003）

| 直す前 | 直した後 |
|---|---|
| 今回は、**最後の問題を解き終わった時点で残り1分。** | 今回は、最後の問題を解き終わった時点で残り時間が1分でした。 |
| 日本語で受けて確実にバッジを取りにいくもよし、私みたいにあえて英語で挑むもよし。 | 文ごと削除した（1-9 を参照） |

### 1-2. 比喩を事実に置き換える

比喩は、何が何をするかに置き換える。ただし、著者が自分の声として選んだ語は残す。（L004）

| 直す前 | 直した後 |
|---|---|
| 効くことは3つ | やるべきことは3つ |
| 要件だけ拾って読む | 要件だけを読む |
| クセのある単語 | 意味を取りにくい単語 |
| 土地勘がある | 多少の経験がある |

著者が残した語の例は「**縛りプレイ**」である。エージェントはこの語を比喩として一度消したが、著者は「そのままでいい」と指示し、公開版では太字にした。著者自身が「壁」と書いた場合も同じように扱う。比喩を消す作業では、著者が書いた語か、エージェントが書いた語かを先に確かめる。

### 1-3. 省略した語を補う

書き手には分かっていても、読者には分からない語を補う。著者の手直しで最も多かったのは、この種類の直しである。（L012）

| AI の下書き | 著者の公開版 |
|---|---|
| 理由は2つあります。 | **英語受験した**理由は2つあります。 |
| 結果は720点で合格でした。 | **試験**結果は720点で合格でした。 |
| re:Invent | **AWS** re:Invent |
| EC2やVPCは出題されません。 | EC2やVPC**といったAWSサービスの技術的な話**は出題されません。 |
| CAF for AI と Responsible AI Lens | **AIBの主な試験範囲である**CAF for AI と Responsible AI Lens |

EC2 の例では、著者は例の後ろに分類を補った。例だけを挙げると、読者は「何の例か」を自分で考える必要がある。

### 1-4. 抽象的な語を、実際に起きたことに置き換える

一般的な語で書ける文は、誰が書いても同じ文になる。著者の体験と、問いの中身が分かる語に置き換える。（L013）

| AI の下書き | 著者の公開版 |
|---|---|
| 参加する前に | ラスベガスに行く前に |
| 英語で読んで英語で判断する経験 | 技術的な話を英語で読んで理解する経験 |
| 何を答えればよいかが分かります | この問題が何を問うているのか、その方向性が分かります |
| 問題文のどこが要件で | 問題文のどこが問題を解くために必要な要件の情報で |
| 英語で受けると何が変わるのか | 英語で受けるときの壁 |

### 1-5. 文と文を接続詞でつなぐ

エージェントの文は、前の文との関係を書かずに次の文を並べやすい。前の文との関係を、接続詞で示す。（L010）

| AI の下書き | 著者の公開版 | 示した関係 |
|---|---|---|
| 今回は、最後の問題を… | **ですが**今回は、最後の問題を… | 前の文と逆の結果 |
| 具体的には、最後の問いの一文を… | **そして**、最初に一番末尾の一文を… | 前の文に続く行動 |
| この措置は、英語で受験するとき以外にも利用できます。 | **なお**この措置は、英語で受験するとき以外にも利用できます。 | 補足 |
| AWSには、…特別措置があります。 | **まずはこれです。**AWSには、…特別措置があります。 | 節の優先順位 |
| AIB-C01はどんな試験か | **そもそも**AIB-C01はどんな試験か | 本題の前提に戻ること |

### 1-6. 短い文の連続を 1 文にまとめる

主語と述語をそろえると、短い文が同じ調子で続きやすい。理由や対比の関係がある 2 文は、1 文にまとめる。（L011）

| AI の下書き | 著者の公開版 |
|---|---|
| 私はこの読み方を英語の受験で身につけました。日本語の試験でも使える読み方だと思います。 | 私はこの読み方を英語での受験で身につけました**が**、日本語の試験でも使える読み方だと思います。 |
| この記事は、英語に自信がない人に向けて書いています。私も英語に自信がありません。 | この記事は、**私のような**英語に自信がない人に向けて書いています。 |

### 1-7. 語尾をやわらかくする

読者に指示する語尾と、論文のような語尾を、著者が読者に話しかける語尾に変える。（L016）

| AI の下書き | 著者の公開版 |
|---|---|
| 〜を書きます。 | 〜を書いて**いきます**。 |
| 〜と考えておいたほうがよいと思います。 | 〜を**意識しておくとよい**と思います。 |
| 申請してください。 | 申請**しましょう**（自戒） |
| 申請し忘れました。 | 申請し忘れて**しまいました**。 |

`なので` のような軽い話し言葉は、公開版にも残っている。ブログは読み物なので、スライドのように書き言葉だけにそろえない。

### 1-8. 著者の感情と本音を入れる

著者の感情、迷い、照れ、自分への戒めが入ると、文に書き手の存在が出る。エージェントはこれらを創作しない。著者に聞くか、著者が入れる場所を残す。（L014）

| 実際に著者が入れた言葉 | 働き |
|---|---|
| 残り時間は**まさかの**1分 | 著者の驚き |
| （**厳密には45秒くらい？**） | 細部の記憶と、断定しない態度 |
| （**おこがましいですが**） | 大きな目標を語るときの照れ |
| ESL +30分を必ず申請しましょう（**自戒**） | 申請を忘れた本人であること |
| **わりと**苦労しましたが | 程度を強調しすぎないこと |
| **よければ**ご活用ください | 読者への距離感 |
| **シンプルに**難しい単語 | 著者らしい分類の言葉 |

### 1-9. 不要な文を削る

文を整える前に、削れないかを考える。著者は次の文を削った。

- エージェントが足した解説（`most cost-effective` などの言葉を説明する段落）
- 読者の関心から外れた宣伝や予告（自作サイトの余談、バッジの再告知、コメントの呼びかけ）
- 前の文と重なる文（「事前に覚えておく必要があります」）
- 確かめていない手順（「試験を予約する前に申請してください」「申請はAWS認定アカウントから行います」）

（L019）

## 2. 判断に迷うとき

ルールどうしがぶつかるときは、次の表に従う。

| 迷う点 | 判断 | 根拠 |
|---|---|---|
| 比喩を消す指示と、著者の表現 | 著者が書いた語は残す。エージェントが足した比喩は消す | 縛りプレイの指示（L004） |
| 文を短くすることと、文のつながり | 意味のつながる 2 文は、長くなっても 1 文にまとめてよい | 公開版の「〜しましたが、〜」（L011） |
| 括弧を避けることと、著者の声 | スライドでは避けるが、ブログでは本音や補足に使ってよい | 公開版の（自戒）（おこがましいですが） |
| 話し言葉と書き言葉 | です・ます調を基本にし、軽い話し言葉を残してよい。用語の定義と事実は正確に書く | 公開版の「なので」「わりと」 |
| 「私は」の繰り返し | 指示なく省かない。主語を補う指示が先にあり、著者は公開版でも多くを残した | 公開版の前提条件の枠。省く方がよいかは、著者に確かめる |
| 「必ず」のような強い語 | 事実の主張では避ける。著者が読者に勧める言葉としては残してよい | 公開版の「必ず申請しましょう」 |

## 3. エージェントが避ける文

次の言い方は、実際の記事の推敲で消えた。書く前に、言いたいことを事実で書けないかを考える。

| 型 | 実例 | 代わりにすること |
|---|---|---|
| 決め台詞 | 翻訳を待たなくていい。／AIに丸投げするのではなく… | 著者が実際にしたことを書く |
| 派手な比喩 | ラスボス／殴り合う／地図を描く | 何が難しかったかを書く |
| 大げさな題 | 〜したら、ラスボスは試験じゃなく英語だった | 内容をそのまま書く（L020） |
| 並べた選択肢 | 〜もよし、〜もよし | 読者に勧めることを 1 つ書くか、削る |
| 前置き | ここからが本題です。／正直に書くと | 本題から始める |
| 体言止めの連続 | 残り1分。 | 述語まで書く |
| 飾りの過多 | 全節の枠、絵文字、太字の連続 | 枠は記事全体で数個に絞る（L018） |
| 根拠のない一般化 | 日本語で受けるときと同じペースで解くと、時間が足りなくなると思います | 著者の場合の話として書き、原因も著者の言葉で書く（L006） |

## 4. 著者の言葉を扱うときの決まり

- **著者の動機と気持ちを作らない。** エージェントは「国内だけで終わりたくない」と書いたが、著者の考えは「世界水準のエンジニアになり、日本の技術力向上に寄与したい」だった。（L005）
- **著者が話した原因を、別の原因に広げない。** 著者が「単に私の英語力が低いから」と言ったら、その言葉を使う。（L006）
- **著者が直した文は、指示がない限り元に戻さない。** 新しい文は、著者の文に合わせる。（L021）
- **著者の表現を「きれいな表現」に直さない。** 「シンプルに難しい単語」のような言い方も著者の声である。

## 5. 書き終えたときの確認

- [ ] 文の骨格：主語、述語、目的語を読み手が取り違えないか
- [ ] 省略：「何の」「誰の」と聞かれる語が残っていないか
- [ ] 具体性：その文は、著者以外にも書ける一般論になっていないか
- [ ] つながり：各文の頭に、前の文との関係が分かる語があるか。接続詞が無くても関係が分かるか
- [ ] リズム：同じ長さの文と同じ語尾が 3 文以上続いていないか
- [ ] 声：著者の感情や本音が入っているか。エージェントが創作した感情が混ざっていないか
- [ ] 飾り：比喩、決め台詞、絵文字、枠、太字を、消しても意味が変わらないなら消したか
- [ ] 声に出して読んだときに、著者が言いそうな文になっているか。分からないときは著者に確かめる
- [ ] `npm run check -- 記事.md` の警告を 1 件ずつ確認したか
